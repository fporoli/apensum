# Notes (Apensum plugin `notes`): the example plugin

Personal notes per person and organization, in Markdown (shown formatted, the source on demand), visible to their author and to whom they share one with.\
It is deliberately small: copy it to start a new module, and read it next to `docs/PLUGINS.md`.\
The module is off by default; an organization's admin switches it on under Organization settings → Modules.

## The files

| File | What it shows |
|---|---|
| `package.json` (`apensum`) | The manifest: id, plugin API version, the permission object `nav.notes`, the module, the plugin's own Postgres schema `notes`, the API and web entries. |
| `changelog/001-notes.sql` | The schema and its table, the permission rows and their default grants, as a Liquibase changeset by `notes`. |
| `api/db/schema.ts` | Generated by `npm run dev:introspect` from the database; never edited by hand. |
| `api/index.ts` | `defineApiPlugin`: everything the plugin adds to the API. |
| `api/notes.controller.ts` | A handler that authorizes itself like the core's: the caller from the token, the permission via `can`, errors returned as `{ ok: false, error }`, writes recorded in `versions`. |
| `api/sharing.ts` | Forwarding by e-mail: the addresses, a limit per hour, the mail in the recipient's language (pure, tested). Sharing with colleagues or a department keeps the recipients on the note (`shared_with`, `changelog/002-shares.sql`) and notifies them (a text key, shown in the reader's language). |
| `api/assistant-tools.ts` | Tools for the AI assistant (`notes_list`, `notes_add`, `notes_update`, `notes_delete`): each calls the controller as the caller, so the assistant can do nothing the page doesn't allow. |
| `web/index.tsx` | `defineWebPlugin`: the texts and one page in the core's "Personal" navbar group. |
| `web/Notes.tsx` | The page, built from the core's building blocks (`@worktime3/web/plugin`). |
| `web/texts.ts` | The texts in English, German, French and Italian. |
| `test/` | The controller's checks, the texts and the changelog against the manifest; `npm test` in the core runs them. |

## Development

It lives in the core's repository, so `npm run build`, `npm test` and `npm run dev:migrate` include it.\
Rename the id (folder, manifest, schema, permission object, texts) before building your own module on it: every name a plugin adds starts with its id.
