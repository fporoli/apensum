# Plugins and the modules built on them

The plugin system and each plugin: billing, hrplus, whistle, notes, expenses (with booking).\
Moved from CLAUDE.md as it was; CLAUDE.md keeps the rules that apply everywhere and points here.

- Plugins (`plugins/<id>`, docs/PLUGINS.md): a folder with a package.json `apensum` manifest (`id` = folder name, `apensumApi` = `PLUGIN_API_VERSION` of `packages/shared/src/pluginApi.ts`, checked at API start and web build: bump it when a contract change can break existing plugins; every name a plugin adds (tables, permission objects, reports, pages, ...) starts with its id, checked by `namespaceMismatch`, `legacyNames: true` only for expenses, optional `module` registered via `registerModule`, optional `permissions` = its permission objects, registered via `registerPermissionObjects` by the API and the web app, `api` = built entry, `web` = TS entry).\
  Not npm workspaces and no dependencies of their own (everything resolves from the root `node_modules`), so a private plugin cloned into the folder (gitignored except the bundled example `plugins/notes`) changes neither the lockfile nor `npm ci`.\
  A plugin imports the core only through the contracts `@worktime3/api/plugin` (+ `@worktime3/api/schema`) and `@worktime3/web/plugin`; extend those files, never import other core files from a plugin.\
  API: `plugins.ts` loads them in `app.module.ts` (an unbuilt plugin stops the start); `npm run build --workspace=@worktime3/api` compiles them (`scripts/plugins.mjs build`, after the API's declarations).\
  Web: Vite's `virtual:apensum-plugins` (`vite.config.ts`) bundles them; `plugins.ts` merges their texts into the dictionaries and App.tsx / main.tsx / OrganizationSettings.tsx / Approvals.tsx show their pages, nav groups, settings sections, public routes and workflow kinds (label, source, title, Inspect dialog of an approval kind; the API side declares `ApiPlugin.workflows`: actions, source tables with org resolver and record loader, manager routing).\
  Everything a plugin adds to the API is declared in `defineApiPlugin`; `plugins.ts` and `plugin-registrar.ts` register it, plugins call no `register*` themselves.\
  Tests: `plugins/<id>/test` (`*.test.ts` via tsx, `*.test.mjs` via node), run by `npm test` (`scripts/plugins.mjs test`).\
  Private plugins reach the images through the repository variable `PRIVATE_PLUGINS` (`<id>=<owner>/<repo>[@<ref>]`) and secret `PLUGINS_TOKEN` (`.github/actions/private-plugins`, used by `build-push` and `vps`, not by CI); `build-push` refuses while its images are public (docs/PLUGINS.md, "Builds and deploys").\
  The core must work without plugins: CI job `core-only` (empty `APENSUM_PLUGINS_DIR`, `scripts/smoke-no-plugins.mjs`); grants on objects outside the catalogue (a missing plugin's) count for nothing (`mergePermissionRows`).\
  Database: `plugins/<id>/changelog/db.changelog-master.xml` (same rules as the core's, author = plugin id) runs after the core's: the migrate image's entrypoint `infra/liquibase/apensum-migrate.sh` (an `update` is one Liquibase run over a master including the core's and every plugin's; APENSUM_CHANGELOG=core|<id> limits it and runs them one by one), changesets recorded as `<id>/changelog/<file>` either way; compose and `migrate.mjs` mount `plugins/`, the Azure/VPS workflows stage them (`scripts/plugins.mjs stage-changelogs` -> `infra/liquibase/plugins`); `db:status` checks each changelog.\
  A plugin's permission rows and default grants live there; its tables may be in `public`.\
  Tables a plugin lists in `apensum.tables` are introspected into its own `api/db/schema.ts`, not the core's (expenses: expenses, expense_reports, expense_report_items; their old changesets and the rows 035/037/049 made stay in the core's changelogs, and `LEGACY_PLUGIN_TABLES` in `apps/api/drizzle.config.ts` keeps them out of the core's schema even without the plugin, as in CI).
- Customer invoicing (private plugin in `fporoli/apensum-billing`, cloned into `plugins/billing`, named in `PRIVATE_PLUGINS`; `requires: ["expenses"]`; module `billing`, licensed, default off; own schema `billing`; `nav.billing` org-wide, HR and billing_admin): customers, a customer and hourly rate per project (and per person), invoices from approved project hours (the person's project timesheet of the month approved) and billable expenses of approved reports up to the period's end (older ones left off come again), each line ticked or left open for the next invoice, each billed once (`billing.invoice_items`; a draft reserves, delete or cancel frees), an expense written off never comes (`billing.written_off`), the PDF lists the billed expenses on a page of its own (never the internal comment), issued with the next number and a QR reference (QR-IBAN) or RF reference, PDF with the Swiss QR bill (`api/invoice-pdf.ts`, the API's `qrcode` dependency), booking export (CSV, Banana); pure rules in `plugins/billing/shared/billing.ts`, see its README.\
  The invoice PDF can carry copies of the billed expenses' receipts (`?receipts=1`, pdf-lib).
- HR plus (private plugin in `fporoli/apensum-hrplus`, cloned into `plugins/hrplus`; module `hrplus`, licensed, default off; own schema `hrplus`; `nav.hrplus` people scopes: own / reports / HR edit all): on- and offboarding checklists from templates (items as tasks to departments through `FlowsService.openTask`, done when resolved; the person's loans to return on offboarding), certificates with kinds, validity and required ones (valid / expiring / expired / missing, a reminder notification once before the end, `HRPLUS_REMINDERS=off`), inventory and loans, a history per item and per person's certificates of a kind (`shared/history.ts`, from the loans and the core's `versions`; certificate entries carry `org_id`, since an account spans organizations); see its README.\
- Reporting office (private plugin in `fporoli/apensum-whistle`, cloned into `plugins/whistle`; module `whistle`, licensed, default off; own schema `whistle`; `nav.whistle` org-wide: see = report, edit = handle, HR by default): anonymous reports from the public page `#/whistle/<slug>` or the app with a case code and key (bcrypt hash only, no account or IP stored), confidential ones with the name for the office only, the EU directive's deadlines, notifications without contents; see its README.\
- Notes (`plugins/notes`, module `notes`, default on, own schema `notes`): the open example plugin, personal notes per person and organization (`nav.notes`, own only) in Markdown (the core's `MarkdownView`/`MarkdownHelp` in the web contract: markdown-it in the app, `markdownRender.ts`, no HTML, safe links in a new tab, pictures as text, task lists; the website, News and mails keep the shared `markdown.ts`), shared with colleagues or a department as it is then (`notes.notes.shared_with`, notified) or forwarded by e-mail to any address (at most 10, a limit per hour, Reply-To the author; colleagues among them get it shared with the link), with the assistant's tools; keep it small and complete, it is what docs/PLUGINS.md and the website's plugin page point to.\
- Expenses (private plugin in `fporoli/apensum-expenses`, cloned into `plugins/expenses` and named in `PRIVATE_PLUGINS` like hr and cases; module `expenses`, default on, no license; everything expense-specific is in the plugin: tables (`api/db/schema.ts`), changelog, form (`shared/form.ts`, registered via `ApiPlugin.forms`), booking (`shared/booking.ts`), report, team views, documents, payroll, workflow, Home quick action (`homeAction`); the core only keeps the organization's currency list under static_data `expenses`/`currency` and the old changesets): the receipt (one file) is attached in the expense form itself (drop, paste, paperclip) and shown there when editing; the list is newest first.\
  `receiptCapture.tsx` adds a photo (phone camera via `capture`, webcam dialog on a computer), a screen area (`getDisplayMedia` + crop) and a QR code: the PC creates a hand-off (`receipt-handoffs`, in memory, 10 min, one file, `ReceiptHandoffService`), the phone opens `#/receipt/<token>` (`PhoneUpload.tsx`, rendered by `main.tsx` without login, token = credential) and sends the photo; the PC polls, takes the file into the form and uploads it as usual.
  Expense processing (Expenses group, `nav.expenseProcessing`, HR only since the plugin's 005; `expense-processing.controller.ts`, `shared/processing.ts`): the reports ready (approved, and those processed before payment runs, without a run); HR selects some and the popup shows the text for accounting (name, personnel number, amount per cost centre and currency, cost centre = the project's `cost_item` else the department, submission date, workflow id; copy or CSV; the table shows each report's number (`expense_reports.number`, per organization, set by a trigger, plugin changeset 007) and total, its cost centres on hover; a person without a personnel number can't be processed, `personnel-number-missing`), then makes a payment run of them (they become `processing_finished`).\
  Each report's details (expenses, VAT type, receipt there or missing) can send it back for correction (plugin changeset 014, `POST expense-processing/:id/correction`, a note per expense in `expenses.correction_note`, status `correction`): the person changes only the receipt and the texts (`CORRECTION_FIELDS`, the API ignores the rest), no new approval, and hands it back (`expense-reports/:id/correction-done`, approved again); an expense in any other submitted report is locked in the API too (`expense-locked`).\
  Billed on to the customer (`expenses.billable`, plugin changeset 015, `POST expense-reports/:id/billable`): whoever may decide the report's pending step sets it per expense of a project in the approval dialog, never the person; removing the project clears it.\
  The expense form never asks for the VAT type (the category's default or what receipt recognition read is stored; Finance corrects it).\
  Finance checks a run's expenses (`GET expense-payruns/:id/expenses`, receipts readable for whoever sees the run, `RunExpenses.tsx`) and splits one by VAT (plugin changeset 016, `expense_vat_lines`, `PUT .../expenses/:expenseId/vat-lines`, `nav.expensePayout` edit, open runs only, `shared/vatSplit.ts`): lines per VAT type with an optional cost centre, adding up to the booked amount, booked instead of the expense (`bookedLines` in `processingReports`); cost centres are edited only there, HR's processing shows them.\
  Payment runs (plugin changeset 012, `expense_payruns`: number per organization by a trigger, `run_date`, status open/paid/cancelled; `expense_reports.payrun_id`; `payrun.controller.ts`, web `PayRuns.tsx`, page "Payment runs" = `nav.expensePayout` (011, HR by default, for an organization's own finance role)): reports processed and paid together; a run has its own configurable workflow (kind `expenses.payrun`, `firstStepDecides: false`: `review` = a second person approves it, sending it back cancels it; `pay` = paid, the run and its reports `finished`; facts `total`, `reports`; default: paid only); the run's booking export (`shared/accounting.ts`: one gross line per report, expense account, VAT code and cost centre against the credit account, generic CSV or Banana's import file; the payout, with the salary or by accounting, the accounts and the VAT codes per rate in Organization settings → Expense accounting, `organizations.settings.expenses.accounting`, `expense-accounting.controller.ts`; paid by accounting = the payroll export leaves the expenses out), its payment file (paid by accounting only, and only once its workflow waits at the payment: `shared/pain001.ts`, pain.001.001.09 as the Swiss Payment Standards describe it, CHF and EUR, one payment per report and currency to the first valid IBAN of the person's basic data `bankAccounts`, from `payoutIban`/`payoutBic` in Expense accounting; made by the API, stores nothing, audited without names or amounts), cancelling (before paid: its reports back among the approved ones).\
  Each expense has a required item text (`description`, plugin changeset 013, what a customer may see when it is billed on; mileage suggests "Fahrt 120 km", an allowance its name, receipt recognition a text) and an optional internal note (`comment`, never shown to a customer); older expenses have no text.\
  VAT per expense (plugin changeset 008 `expenses.vat_kind`, `shared/vat.ts`): standard, accommodation, reduced or none, the Swiss rate from the expense date; the form prefills the category's default, none for mileage, flat-rate allowances and receipts not in CHF, receipt recognition reads the rate; the booking export books one line per VAT code (`vatCodes` per type in Expense accounting, none = not registered for VAT) with the VAT amount, per expense at its date's rate.\
  Each expense category's own account and default VAT type are its properties (`expenses`/`expense_category` maps keys to `{account, vat}`, plugin changeset 009, `categoryProperties`, `api/categories.ts`); Expense accounting holds the rest (payout, credit, default, mileage and allowance accounts, VAT codes, the account to pay from).\
  The report's workflow is the configurable kind `expenses.report` (`EXPENSE_REPORT_CATALOGUE`: block `review` only, a decision; facts `total`, `categories`, `requester.management`; default the manager's review (back)); processing and paying are the payment run's; reports still in an older workflow's processing or payment step leave it when they go into a run (`payrun.event.inRun`); `submitted_processing` and `request_payment` are older in-between stages that still go into runs.\
- Expense booking (077, `plugins/expenses/shared/booking.ts` `bookExpense`, used by the form's preview and by `expense-booking.ts` on create/update): people enter the receipt's amount and currency; the API books `value` in the org's reporting currency (`settings.defaultCurrency`, else CHF) with the hand-kept exchange rate in force on the date (the core's exchange rates, below) and stores it in `expenses.exchange_rate`; no rate = `exchange-rate-missing`; the form's preview reads rates, mileage and allowances from the plugin's `GET expense-booking`.\
  Exchange rates are the core's (100, table `exchange_rates`, `exchange-rates.ts` `effectiveRates`/`exchangeRatesOf`/`reportingCurrencyOf` in the plugin contract, `exchange-rates.controller.ts`, `packages/shared/src/exchangeRates.ts` `exchangeRateOn`/`validateExchangeRate`, Organization settings → Exchange rates `ExchangeRateSettings.tsx`, `nav.orgSettings` edit), for any module that converts amounts.\
  Rows with `organization_id` NULL are the defaults for every organization (EUR, USD, GBP to CHF from 2026-01-01, core changeset 100, first made by the expenses plugin's 002; a new year's defaults = a new core changeset), read-only and shown as "Standard"; an organization with its own rates for a currency uses only those for it (`effectiveRates`).\
  Mileage is category `mileage` (offered by the form, in no category list): `quantity` = km x the rate per km in force (static_data `expenses`/`mileage_rate`, key = valid from, global 0.70, org copy overrides), stored in `unit_rate`.\
  Flat-rate allowances (Pauschalspesen) are category `allowance` (offered by the form when the organization has amounts): `sub_category` = the type (static_data `expenses`/`allowance`, the plugin's 006: breakfast, lunch, dinner, overnight, half and full day away, without amounts globally), `quantity` = the count, booked at the organization's amount in force on the date (`{type: {validFrom: amount}}` in its copy, Organization settings → Flat-rate expenses, `POST expense-allowances`, `nav.orgSettings` edit), no receipt needed; the payroll export has them apart (`expensesAllowances`, Abacus 3010, Lohnausweis 13.2; effective expenses 3000).\
  Booked expenses never change with later rates; older ones in another currency stay as they are ("not converted") until edited.\
  Never trust a client `value`.\
  Receipt recognition (`expense-receipt.ts`, `ExpenseReceiptService`, `POST expenses/scan-receipt`): photo or PDF text to Azure OpenAI (Switzerland) only, for every org with expenses when the instance has it, through `AiBudgetService` (kind `receipt`, the org's AI monthly limit, `orgMonthlyLimitChf`); returns a suggestion, stores nothing.\
  The expense API/web files named here live in `plugins/expenses/{api,web}`.
